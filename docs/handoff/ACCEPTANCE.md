## 2. 认证与角色

必须使用生产构建验证，不能依赖固定开发管理员。

| 编号 | 检查 | 通过条件 |
| --- | --- | --- |
| A01 | 未登录 | bootstrap、账号、任务、日志等业务接口返回 401；登录入口可用 |
| A02 | 伪造平台头 | 自带 oai-authenticated-user-* 不能取得任何身份 |
| A03 | 首位管理员 | 由受控命令创建；空密码/弱默认配置不能直接启动成公开管理员 |
| A04 | 登录/退出 | 正确密码成功，错误密码失败；退出后原会话失效 |
| A05 | 会话管理 | 过期、密码重置、成员移除或禁用后原会话按规则失效 |
| A06 | Cookie/CSRF | 正式 HTTPS Cookie 属性正确；跨站写请求被拒绝 |
| A07 | 角色授权 | admin可管理成员与令牌；editor可导入/执行/复核；reviewer可复核但不能导入/执行；viewer不能写 |
| A08 | Token | 只展示一次，保存散列，角色限制正确，撤销立即失效 |
| A09 | 代理信任 | 真实HTTPS POST正常；外来Host/转发头不能改变可信来源 |
| A10 | 频率与错误 | 登录有合理限速；错误不泄露密码散列、令牌或异常栈 |
| A11 | 迁移成员状态 | 旧Sites user_id不被当作本地账号已激活；新凭证与原成员角色正确关联 |

### 旧测试如何使用

现有 `node scripts/test-backend.mjs` 和 Python 模型协议测试可作为业务回归基础。`tests/integration-smoke.py` 默认只接受回环地址，并使用原开发身份语义；应为 Node 生产会话或受控测试令牌增加独立适配，不直接删除地址保护后指向生产。

Node 新增检查集中在真正变化的数据库适配、身份、代理、容器持久化和恢复，不为未改动的纯展示部分堆叠无意义测试。
